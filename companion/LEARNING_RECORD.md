# 학습 완료 점검과 실습 기록 {#learning-completion}

책을 덮기 전에 자신의 Mini CloudShop을 설명하는 작은 결과물 묶음을 만듭니다. 성공 화면 하나보다 구조·실행·장애·회복을 이어 설명하는 기록이 중요합니다.

| 점검 영역 | 남길 결과물 | 복습 위치 |
|---|---|---|
| Image와 실행 | Image 식별 정보와 Container 실행 명령 | 5·6·11장 |
| 요청 경로 | Web → API → Redis 및 Ingress → Service → Pod 그림 | 7·17·19·20장 |
| 데이터 수명 | 교체 전 저장, 교체 후 읽기 결과와 보존 경계 | 8·18장 |
| 선언과 조정 | Pod 교체 전후 관찰과 Deployment 역할 설명 | 15·16장 |
| 장애 진단 | 상태·로그·이벤트, 가설 하나와 회복 판정 | 부록 E |
| 정리와 재현 | 삭제 대상·남길 데이터·다시 실행할 순서 | 20·21장 |

## 스스로 평가하기

각 영역에 0·1·2점을 표시합니다. **0점**은 재현하거나 설명하지 못함, **1점**은 예제를 따라 실행했지만 근거 설명이 부족함, **2점**은 자신의 환경에서 재현하고 관찰 근거와 한계를 설명할 수 있음입니다. 총점은 12점이지만 합계보다 0점 영역을 먼저 보완하세요. 이 점수는 학습 진단용이며 프로덕션 운영 자격을 뜻하지 않습니다.

## 한 번의 실험을 남기는 기록지

아래 양식을 복사하거나 배포 묶음의 `companion/LEARNING_RECORD.md`를 사용합니다. 장애마다 새 기록을 만들고 실패한 가설도 지우지 않습니다.

| 항목 | 기록할 내용 |
|---|---|
| 실험 식별 | 날짜·책·장·실험 이름 |
| 환경과 대상 | OS·도구 버전·Context·Namespace·Container 또는 Pod |
| 시작 상태 | Image 식별 정보·복제 수·저장 데이터·정상 응답 |
| 가설 | 의심하는 경계 한 곳과 그 이유 |
| 기대 결과 | 변경하면 어떤 상태 또는 응답이 달라져야 하는가 |
| 실행과 증거 | 명령·시각·핵심 출력·관측 위치 |
| 판정과 반례 | 기대와 실제 차이·가설을 지지하거나 반박하는 증거 |
| 회복과 정리 | 되돌린 변경·회복 확인·삭제 대상·남긴 데이터 |
| 다음 질문 | 아직 확인하지 못한 조건과 다음 관찰 한 가지 |

다른 사람이 이 기록만 보고 같은 대상을 찾아 실험을 설명할 수 있는지 확인하세요. 비밀번호·토큰·개인 데이터는 기록에서 제거합니다.
